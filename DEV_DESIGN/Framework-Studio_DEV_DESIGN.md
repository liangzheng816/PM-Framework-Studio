# Dev Design — PM Studio (Retroactive)

Written retroactively to document the technical architecture, implementation patterns, and deployment pipeline of PM Studio.

> **Updated 2026-04-09:** Homepage (`/`) is now the AI PM Coach chat UI (see `AI-PM-Coach_DEV_DESIGN.md`). CI/CD now includes a validate job, actions pinned to v4, API backend at `api/`, Bicep IaC at `infra/`, and runtime app settings configured on the SWA resource.

## 1. Product overview

PM Studio is a premium web application teaching 100 product management frameworks through interactive browsing, comparison, and discovery. It is a fully static site (no server runtime) deployed to Azure Static Web Apps.

- **Live URL:** https://salmon-moss-07f46dd1e.2.azurestaticapps.net/
- **Source repo:** https://github.com/liangzheng816/framework_studio
- **Deployment:** Azure Static Web Apps via GitHub Actions (auto-deploy on push to `main`)

## 4. Architecture decisions

### 4.1 Fully static output

```typescript
// next.config.ts
const nextConfig: NextConfig = {
  output: "export",
  pageExtensions: ["js", "jsx", "md", "mdx", "ts", "tsx"],
};
```

`output: "export"` generates pure HTML/CSS/JS into `out/` (118 pages). No Node.js runtime at deploy time. This enables CDN-only hosting on Azure Static Web Apps with instant page loads.

**Trade-off:** No API routes, no server-side rendering at request time. All dynamic behavior is client-side (search, collections, compare, finder).

### 4.2 Filesystem-based content with in-memory cache

`lib/frameworks.ts` reads all 100 MDX files from `content/en/frameworks/` at build time using `fs.readdirSync` + `gray-matter`. Results are cached in a module-level `_cache` variable so repeated calls during static generation don't re-read disk.

```typescript
const CONTENT_DIR = path.join(process.cwd(), "content/en/frameworks");
let _cache: Framework[] | null = null;

function readAllFrameworks(): Framework[] {
  if (_cache) return _cache;
  const files = fs.readdirSync(CONTENT_DIR).filter(f => f.endsWith(".mdx"));
  // ... parse each with gray-matter, sort by order
  _cache = frameworks;
  return frameworks;
}
```

**Why not a database:** 100 frameworks is small enough to hold in memory. Filesystem-based content enables git-tracked content changes, easy diffing, and zero infrastructure beyond the repo.

### 4.3 Server/client split pattern

Pages that need interactivity follow a consistent pattern:

```
app/{route}/page.tsx          (server component — loads data at build time)
app/{route}/{route}-client.tsx (client component — handles user interaction)
```

Examples:
- `explore/page.tsx` loads all frameworks → passes to `explore-client.tsx` for search/filter
- `compare/page.tsx` loads frameworks → passes to `compare-client.tsx` for side-by-side UI
- `finder/page.tsx` wraps `finder-client.tsx` for the guided wizard
- `collections/page.tsx` wraps `collections-client.tsx` for localStorage display

This avoids marking entire pages as `"use client"` while keeping the server-generated HTML minimal and fast.

### 4.4 Client-side search via Fuse.js

Search is fully client-side using a pre-built index:

1. `data/search-index.json` contains all 100 frameworks with `slug`, `title`, `aliases`, `category`, `summary`, `best_for`, `stage`
2. Root layout imports the index and passes it to `ClientShell` → `CommandPalette`
3. `CommandPalette` initializes a Fuse.js instance for fuzzy search
4. Triggered by `Cmd+K`, `/`, or clicking the search button in the navbar
5. ARIA combobox pattern for accessibility

**Why not server-side search:** Static export means no server at runtime. The full index is ~40 KB — negligible for client-side loading.

### 4.5 localStorage for client-side state

Two features use `localStorage`:
- **Collections** (`lib/collections.ts`): saved frameworks stored at key `fs:collections`
- **Theme** (if applicable): light/dark preference

No server-side persistence, no user accounts. All state is browser-local.

### 4.6 Next.js 16 async params

Next.js 16 changed `params` and `searchParams` to async Promises. All dynamic route pages use `await params`:

```typescript
export default async function FrameworkPage({
  params,
}: {
  params: Promise<{ slug: string }>;
}) {
  const { slug } = await params;
  // ...
}
```

### 4.7 Static generation of all framework pages

`generateStaticParams()` in `app/framework/[slug]/page.tsx` pre-renders all 100 framework pages at build time:

```typescript
export async function generateStaticParams() {
  return getAllSlugs().map((slug) => ({ slug }));
}
```

Each page includes JSON-LD structured data (`Article` schema) for SEO.

### 5.1 migrate-content.ts

Transforms raw source markdown into enriched MDX:
- Reads `PM_Frameworks/framework_manifest.json` for metadata (order, group, confidence)
- Parses each source `.md` file for sections (When to use, How it works, etc.)
- Generates structured YAML frontmatter with 17+ fields
- Maps category labels to slugs via `CATEGORY_SLUG_MAP`
- Derives slug from filename: `001_design-thinking.md` → `design-thinking`
- Extracts companion frameworks, inputs, outputs from content
- Writes to `content/en/frameworks/{slug}.mdx`

### 5.2 Frontmatter schema (per MDX file)

```yaml
title: string
slug: string
aliases: string[]
category: CategorySlug          # 8 values
categoryLabel: string
summary: string
best_for: string[]
stage: string[]                 # discovery, research, definition, ideation, validation, etc.
complexity: low | medium | high
time_to_apply: string
team_size: string
inputs: string[]
outputs: string[]
companion_frameworks: string[]  # slugs — drives related framework discovery
confidence: high | moderate
canonical_status: string
order: number                   # controls display sorting (1–100)
```

### 6.4 Motion

All animations use the same spring easing: `cubic-bezier(0.22, 1, 0.36, 1)`.

```typescript
// lib/motion.ts
fadeInUp:         opacity 0→1, y 16→0, 400ms
staggerContainer: stagger children at 60ms intervals
staggerItem:      opacity 0→1, y 12→0, 350ms
scaleIn:          opacity 0→1, scale 0.95→1, 300ms
```

`prefers-reduced-motion` respected globally via CSS: `animation-duration: 0.01ms`.

### 6.5 Spacing, radius, elevation

```

```

### 7.1 Homepage

```

  └── imports search-index.json → passes to ClientShell (for global search)
  └── renders NavBar, Footer

page.tsx (server)
  ├── getFeaturedFrameworks(6) → editorial picks from frameworks.ts
  ├── getCategoriesWithCounts() → 8 categories with framework counts
  └── renders:
      ├── Hero (animated, Framer Motion)
      ├── CategoryRibbon × 7 (horizontal scrollable strips)

      └── CTA → /explore
```

### 7.2 Framework deep-dive

```
app/framework/[slug]/page.tsx (server, statically generated)
  ├── generateStaticParams() → all 100 slugs
  ├── getFrameworkBySlug(slug) → single framework with content
  ├── getRelatedFrameworks(slug, 4) → ranked by: companions > same category > same stage
  └── renders:
      ├── Breadcrumb (Home / Category / Title)
      ├── Header (title, category badge, confidence badge, save button)
      ├── Metadata grid (complexity, time, team size, inputs, outputs)
      ├── Sections (parsed from markdown: When to use, How it works, etc.)
      ├── Sidebar (sticky nav of section headings — desktop only)
      ├── SourceNotes (collapsible attribution panel)
      ├── Related frameworks (FrameworkCard × 4)
      ├── MobileActionBar (sticky bottom: save, compare, share)
      └── JSON-LD <script> (Article schema)
```

### 7.3 Explore / search

```
app/explore/page.tsx (server)
  └── getAllFrameworks() → 100 frameworks

explore-client.tsx (client)
  ├── Fuse.js fuzzy search on title, aliases, summary, best_for
  ├── Category filter chips (multi-select)
  ├── Grid / list view toggle
  └── FrameworkCard grid with stagger animation
```

### 7.4 Related framework discovery

`lib/frameworks.ts` → `getRelatedFrameworks()` uses a 3-tier ranking:

1. **Explicit companions** — `companion_frameworks` array in frontmatter (strongest signal)
2. **Same category** — frameworks in the same `CategorySlug`
3. **Stage overlap** — frameworks sharing at least one `stage` value

Returns up to `limit` results (default 6), deduplicating across tiers.

### 7.5 Collections

```
lib/collections.ts
  localStorage key: "fs:collections"
  Default collection: { id: "saved", name: "Saved Frameworks", frameworkSlugs: [] }

  getCollections()         → read + ensure default exists
  isFrameworkSaved(slug)   → check if any collection contains slug
  toggleSaveFramework()    → add/remove slug from collection
  createCollection(name)   → new collection with timestamp ID
  deleteCollection(id)     → remove (cannot delete "saved")
```

### 9.2 Runtime app settings (critical)

The workflow `env:` block only provides `ANTHROPIC_API_KEY` at **build time**. Azure Functions need it as a **runtime** application setting on the SWA resource:

```bash
az staticwebapp appsettings set --name pmframeworkstudio \
  --setting-names "ANTHROPIC_API_KEY=<key>" "COACH_MODEL=claude-sonnet-4-6" "COACH_MAX_TOKENS=4096"
```

### 9.3 Infrastructure as Code

`infra/main.bicep` + `infra/main.bicepparam` define the SWA resource and all app settings declaratively:

```bash
az deployment group create --resource-group pmframeworkstudio_group \
  --template-file infra/main.bicep --parameters infra/main.bicepparam \
  --parameters anthropicApiKey='<key>'
```

4. Run `npm run build` to verify
5. Push to `main` → validate job runs lint + typecheck → deploy to Azure

## 12. Accessibility

- **Skip nav**: `components/layout/skip-nav.tsx` → `#main-content`
- **Focus visible**: 2px `--color-accent` outline with 2px offset (globals.css)
- **Reduced motion**: `@media (prefers-reduced-motion: reduce)` sets all animation to 0.01ms
- **ARIA combobox**: Command palette search with proper roles and keyboard navigation
- **Selection highlight**: `::selection` uses accent color at 30% opacity
- **Semantic HTML**: `<header>`, `<nav>`, `<main>`, `<article>`, `<footer>`
- **Target**: WCAG 2.2 AA

## 13. Performance targets

From PRD §25:
- Lighthouse score > 90
- LCP < 2.5s on mobile
- Pure static HTML — zero server latency
- Fuse.js search index loaded inline (~40 KB)
- Fonts loaded via `next/font/google` with `display: "swap"` (no FOIT)
