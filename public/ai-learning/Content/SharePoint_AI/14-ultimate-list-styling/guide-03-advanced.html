Multiple skills, one consistent brand

Two skills, side by side, applied to every list in a site. How to layer formatting know-how with brand know-how — and what to do when a session already started.

Both skills, layered

With the list-formatting skill and the forest style skill both loaded, the AI now has two pieces of guidance to combine: how SharePoint formatting works (the technical reference) and what the brand demands (design tokens and rules). The same style this as a timeline prompt produces a timeline that follows the forest palette and spacing.

Stacking skills is multiplicative. The styling skill chooses a pattern from the catalog. The style skill constrains how that pattern looks. The output respects both.

This is the practical version of the rule from Guide 02: variability is fine when you want exploration, harmful when you want consistency. Adding a style definition skill is how you regain consistency without losing creative variation in layout.

The style skill doesn't override the formatting skill. They cooperate — one picks the structure, the other picks the colours, type, and rhythm inside that structure.

Loading a new skill mid-session

The author calls out a small gotcha: when you add a new skill to a site mid-session, the AI doesn't automatically pull it in. New sessions get the new skill automatically; current sessions need an explicit nudge — load the new skills — to refresh.

Skills are loaded at session start. If you add one after starting, ask the AI to load skills before your next styling request.

This is small but easy to miss. If a styling result looks unbranded after you just uploaded the style skill, the most likely cause is that the session never picked it up.

The AI doesn't watch the skills directory for new files in real time. Skill discovery is per session — a refresh is needed when you change the set mid-session.

Replica lists as a fair test

To prove the brand consistency story, the author uses a replica of the exact same product launch milestones list. Same columns, same data — but this run has the style skill loaded. The output is recognisably the same timeline shape with the forest brand applied throughout.

A replica list is the cleanest A/B for skill changes. Same data, same prompt — different styling skill set — see what the layering changes.

The replica technique generalises: any time you're tuning a skill, build a few replica lists and run the same prompt on each. You'll see the effect of every added skill directly.

The same prompt across many lists

For the rest of the demo the author stops narrating and just runs the same style this list prompt against a sequence of different lists with different data. Each one comes back styled, and each one carries the forest brand. Different data, different layouts the AI picks, same overall look and feel.

Once the skills are loaded, you scale by repetition. The brand consistency comes from the skills, not from the prompt.

This is the point the demo is making: with the right two skills in place, list styling at scale is no harder than running the same one-line prompt on every list in the site.

Scale here isn't bulk-applying a fixed template. It's bulk-applying the same intent — the AI picks an appropriate pattern for each list and renders it on-brand.
