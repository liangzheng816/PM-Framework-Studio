The mechanism

How it works — reason first, then tell

Composition is assembly, not authoring. The partner runs a six-step flow that grounds a topic in your memory, reasons with the product-management method that fits the decision, locks one narrative spine, assembles many grounded atoms, crafts the output to an executive bar, and checks its own work.

The six-step compose flow

1

Ground

recall --assemble pulls the topic's atoms and expands the top match through the typed-edge graph. If memory is thin, it auto-runs a topic harvest (announced) before composing.

2

Reason with the PM lens silent substance pass

Apply the product-management method that fits the decision the story carries — RICE to defend a priority, JTBD to prove demand, a pre-mortem for risk — to author and pressure-test the evidence. The framework is never named in the output.

3

Frame

Lock exactly one narrative spine — Minto Pyramid, Working Backwards, StoryBrand, Pixar ABT, Golden Circle — and declare which beat each atom fills. One spine, never blended.

4

Assemble

Bind each beat to its grounded atoms: numbers from metric / proof_point, voice from quote, spine from message / narrative, dates from milestone / release. Missing facts become [TBD].

5

Craft

The always-on presentation-craft engine renders the output to an executive bar — PRESENT (a self-contained 16:9 HTML deck) or WRITE (a narrative or document).

6

Check

Report Proof used, Open [TBD], and any sensitivity to screen — so you always know what's grounded and what still needs a fact.

Silent · selective · grounded. The method's thinking is applied, never its label; simple pieces skip the substance pass; and a lens only structures analysis of real atoms — where a number is missing it becomes [TBD], never invented.

The build pipeline build-memory

The core of build-memory is a four-stage pipeline. Each stage persists on its own, so a late failure never loses earlier work — recover with build-memory --from-cache.

01 · HARVEST

Harvest

Pull WorkIQ signals plus file / mail / calendar / Teams activity into the local .signals cache.

02 · EXTRACT

Extract

One local LLM pass turns raw signals into typed entities, prioritizing ingested src-* imports.

03 · UPSERT

Upsert

Deterministic, idempotent merge into Markdown entity files — array union, document dedupe, Graph metadata wins.

04 · INDEX

Index

Rebuild per-collection INDEX.md, the global MEMORY.md hot cache, and edges/INDEX.md.

Targeted topic harvest --topic

build-memory --topic "<text>" [--days 180] gathers signals about a topic like recall — WorkIQ + Graph $search (mail/files) + Teams, ranked by relevance, not recency. The compose/draft flow auto-runs it (announced) when recall is thin.

Frontmatter links become relationships — proof_point —supports→ message, quote —voices→ narrative — so atoms can be joined, not just listed.

one topic → dozens of atoms

Provenance rail

Every entity carries sources, confidence, as_of, and a sensitivity tag, so the agent can avoid stale claims and flag what to screen.

grounded by design

Yours to edit

Plain Markdown with a preserved human ## Notes area safe to hand-edit. Upsert is idempotent, so a re-build never clobbers your notes.

PersonalSecondBrain/memory/

Sensitivity is an informational label. Every atom is tagged (public → customer-nda); when you compose for an external audience the agent flags the confidential / customer-NDA atoms it used so you can screen them before sharing. You stay in control of what leaves the room.

Without the substance pass

“We recommend investing in X. It's strategic, customers want it, and competitors are moving.” Clean — but thin and generic.

With it — silent

“X over Y and Z. ~40% of tenants hit this monthly; removes the #1 trust blocker; +6 pts projected on activation — one sprint, Y and Z fall below the line.” No jargon. Same shape.

The craft bar every output

Answer-first (BLUF)

Lead with the conclusion and the ask; the audience knows it by slide 2–3 and again at the close.

Slide = assertion

Evidence tiers

Quickstart

From the agent folder (agents/communication-partner):

# verify the toolchain, then build memory
node skill/scripts/cli.mjs doctor
node skill/scripts/cli.mjs build-memory --days 14
node skill/scripts/cli.mjs recall "<topic>" --assemble

Then run any communication job:

node skill/scripts/cli.mjs write memo "<topic>"
