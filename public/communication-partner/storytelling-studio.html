Five jobs, one grounded memory

This Studio drives compose — the flagship job. The communication partner runs four more jobs on the same sourced, sensitivity-labeled memory, as zero-dependency CLI verbs you run and relay (node skill/scripts/cli.mjs):

  • Compose — topic → a story or self-contained HTML deck. This Studio → the peer-storytelling composer.
  • Draft — write <type> "<topic>" → a grounded document (prd · blog · mc · newsletter · faq · memo · email · one-pager).
  • Rewrite — rewrite <file> --goal "…" → revise an artifact (tighten · re-tone · re-target · BLUF · convert · de-AI), format-preserving + re-gated.
  • Adapt — adapt <file> --to "memo:CVP, email:field, faq:customers, pitch:end users" → one artifact into N audience-tuned variants.
  • Review — review <file> → a five-persona critique + ranked top fixes (read-only).

Every job grounds in metric/proof_point/quote/message, marks gaps [TBD], and flags sensitivity as an informational label — the user screens external sharing; it is not auto-enforced. Compose and draft start from a topic; rewrite, adapt, and review start from an existing file. When a topic isn't in memory yet, a targeted harvest (build-memory --topic "…" --days 180) gathers it across email · Teams · files · meetings by relevance, then recall finds it.

How this explorer maps to an AI content-generation tool

Every scenario is structured as a reusable generation recipe with five inputs that an AI tool can take as parameters:

  • persona — the author's level (PM → VP), which sets altitude, language, and what they can credibly claim.
  • audience — who receives the story, which sets what they care about and the "so what."
  • trigger — the business moment that calls for the story (launch, review, ask, save).
  • framework — the narrative skeleton that organizes the content (SCQA, Working Backwards, Promised Land…).
  • output — the artifact produced (deck, doc, email, PR-FAQ, script, talking points).

The generation prompt pattern

Each scenario card includes a copy-ready prompt. The general shape is:

Scenario : [SCENARIO] · Topic: [[TOPIC]] Narrative spine: [FRAMEWORK] — [its beats, in order]. Must cover: [the beats that make THIS story complete]. Craft: lead with the answer · titles are assertions · Tier 1–2 proof · one ask. Additional ground truth (optional): [[PASTE CONTENT TO REVIEW/DRAFT, OR ATTACH A FILE]] — treat as PRIMARY over memory. Ground from agents/communication-partner: node skill/scripts/cli.mjs recall "[[TOPIC]]" --assemble Formatting (audience · persona · density · theme · length): ASK ME at runtime — or pre-answer in the Explorer's optional hints.

Building the tool

Use the four data arrays embedded in this file (SCENARIOS, FRAMEWORKS, PERSONAS, AUDIENCES) as your taxonomy/seed data. A prototype flow: user picks scenario → tool pre-fills framework + prompt → user pastes raw material → model drafts the artifact → user iterates on tone/length. The scenario library doubles as a picker UI and a router to the right system prompt.
